WHAT WE'RE BUILDING
───────────────────────────────────────────────────────────────────────────────
A root cause analyzer for performance dips.

Input:  Select a date where stats dropped
Output: Ranked list of hypotheses (campaign issue? delivery? external factor?)
        with confidence scores, in < 1 second

Example:
  📉 Stats dropped 35% on 2026-06-03

  Hypotheses:
  1. UK Royal Mail strike (95% confidence — logged by operator)
  2. PlusVibe API latency spike (85% — API logs confirm 2x slower)
  3. Campaign quality decline (40% — unlikely, reply rates normal)

WHY THIS MATTERS
───────────────────────────────────────────────────────────────────────────────
Right now when stats drop, you check:
  ❌ Is it a client issue? (might be)
  ❌ Is it copy decay? (might be)
  ❌ Is it email account reputation? (might be)
  ❌ Is it infrastructure? (might be)
  ❌ Is it external (strike, ISP outage)? (might be)

You never know for sure. This system tells you.

SOLUTION APPROACH
───────────────────────────────────────────────────────────────────────────────
Collect 6 independent signal categories:
  1. Email account health (warmup %, bounce rate per account)
  2. Infrastructure health (memory, CPU, queue depth, event loop lag)
  3. API health (PlusVibe latency, error rates)
  4. Campaign metrics (sends, replies per client/workspace)
  5. Bounce analysis (hard/soft, per account, trends)
  6. External factors (operator-logged: strikes, ISP outages, policy changes)

Decision tree with 7+ rules that isolates the root cause:
  IF all metrics normal, reply rate down → campaign quality issue
  IF sends down, replies normal → delivery/email account issue
  IF everything down globally → external factor or infrastructure
  ... etc (see DIAGNOSTIC_PLAN.md section 3)

RISK MITIGATION
───────────────────────────────────────────────────────────────────────────────
HIGH RISK:  Decision tree logic (can produce false diagnoses)
            → Mitigate: Test on 10+ synthetic scenarios before shipping
            → Start with high confidence thresholds (>85%)
            → Operator can manually override

MEDIUM RISK: API instrumentation overhead (logging every call = perf regression)
            → Mitigate: Batch logs asynchronously, measure latency impact
            → Sample (1 in 10 calls) if overhead detected

MEDIUM RISK: Query performance on 30 days of signals
            → Mitigate: Add indexes, test EXPLAIN ANALYZE before building
